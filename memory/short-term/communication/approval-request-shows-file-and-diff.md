> Memory: When asking for approval of a change, start with the file it changes, then show the exact text before and after.

When asking the user to approve a change, start each proposed change with the file it changes, then show the exact text before and after. Naming another file first, even only to describe it, makes the user hunt for which file is actually changing.

Example: start with "`core/learn.md`, step 3:", then the old text and the new text. Don't open with "`recall.md` reads the memories, so..." when `recall.md` isn't the file that changes.
