To explain why something behaves as it does, state the cause in a full sentence and walk one small numeric example step by step, because a compressed explanation hides the reasoning from the reader and the mistakes from you. Use tables for lookup data, not for reasoning.

Example: to explain why a memory wasn't promoted, say "promotion needs a use on each of the last 5 active dates", then walk it: the active dates are the 1st to the 5th, the memory was used on the 1st, 2nd, 4th and 5th, so the 3rd is missing and the memory stays in short-term.
