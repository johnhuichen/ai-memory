> Memory: When the user already saw the details in an earlier reply, report only the outcome instead of restating them.

When a reply would repeat what the user already read in an earlier reply, such as a change, its reason or a before-and-after, report only the outcome and leave the rest out. The user has the details in front of them, so restating them costs tokens and reading time and tells them nothing new.

Example: a main reply showed a memory edit with its before-and-after, and then the learn step ran. Wrong: explain again which file changed and why. Right: `**[core learn]** made memory files explicitly not AI-only` and nothing else.
